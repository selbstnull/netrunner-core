# Приглашения к подключению

Приглашение — одна строка `nrxp://…`, в которой есть всё для подключения клиента к узлу:
адрес, ключ узла, входной секрет, при необходимости токен и домен-декой. Её удобно
отправить сообщением, показать QR-кодом или положить в `client.toml`.

> **Приглашение — секрет.** В нём входной секрет узла (и токен, если он есть). Кто его
> увидел, тот может подключиться. Передавайте по закрытому каналу, не публикуйте, не
> сохраняйте в логах и истории оболочки. Для отзыва смените секрет/ключ узла или токен.

## Получить приглашение на сервере

```bash
PROXY_NRXP_PRIVATE_KEY=… PROXY_NRXP_SECRET=… \
netrunner-server --invite --advertise 203.0.113.7:443 \
    --invite-name "мой телефон" --invite-token "$TOKEN" --decoy-host www.debian.org
```

Результат (только строка, в stdout):

```text
nrxp://203.0.113.7:443?pk=abab…ab&secret=cdcd…cd&token=efef…ef&sni=www.debian.org&name=%D0%BC%D0%BE%D0%B9+%D1%82%D0%B5%D0%BB%D0%B5%D1%84%D0%BE%D0%BD
```

Команда не запускает сервер и не пишет в stdout ничего, кроме приглашения (предупреждения
идут в stderr), поэтому годится для скриптов: `URI=$(netrunner-server --invite …)`.

| Флаг | Смысл |
|---|---|
| `--invite` | напечатать приглашение и выйти |
| `--advertise host:port` / `--invite-addr` | публичный адрес в приглашении |
| `--invite-name` | подпись для списка в приложении |
| `--invite-token` / `NETRUNNER_INVITE_TOKEN` | Bearer-токен для узлов с `--require-auth` |
| `--invite-sni` | домен-декой (по умолчанию `--decoy-host`) |
| `--invite-format uri\|toml` | `toml` — блок полей для `client.toml` вместо строки |

Ключи берутся из тех же переменных, что и при запуске узла: `PROXY_NRXP_PRIVATE_KEY` (из него
считается публичный ключ `pk`) и `PROXY_NRXP_SECRET`. В режиме роя (`--swarm-key`) секрет
выводится автоматически; если `PROXY_NRXP_SECRET` задан и расходится с выведенным, команда
завершится ошибкой, а не выдаст приглашение, которое не подойдёт.

## Формат

| Часть | Смысл | Обязательно |
|---|---|:-:|
| `host:port` (до `?`) | адрес узла | да |
| `pk` | публичный статический ключ узла (64 hex) | да |
| `secret` | входной секрет узла (64 hex) | да |
| `token` | Bearer-токен | нет |
| `sni` | домен-декой | нет |
| `name` | подпись; UTF-8, процентное кодирование, пробел — `+` | нет, до 64 символов |

Неизвестные параметры игнорируются — формат расширяем. Повтор параметра, неверная длина hex,
порт 0, управляющие символы в токене/имени и приглашения длиннее 8 КиБ отклоняются.
Разбор и сборка — `netrunner_core::invite::Invite` (`parse`, `to_uri`, `to_toml`).

## Подключить клиент

```bash
netrunner-client --invite 'nrxp://…'          # виден в ps — лучше так:
NETRUNNER_INVITE='nrxp://…' netrunner-client
```

или в `client.toml`:

```toml
invite = "nrxp://203.0.113.7:443?pk=…&secret=…&sni=www.debian.org"
```

Правила: явные `--remote-address`, `--sni`, `--auth-token`, `--node-secret`, `--node-public-key`
важнее приглашения; приглашение из CLI/окружения важнее одноимённых полей TOML; `invite` и
`remote_address`/`node_secret`/`node_public_key` в одном TOML — ошибка. Клиент пока принимает
только IPv4-адреса узлов.
