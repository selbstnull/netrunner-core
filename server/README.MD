# Крейт `server` — серверная часть прокси

Тонкая обвязка вокруг ядра ([`core`](../core)): принимает замаскированные
TLS-соединения, проверяет, что это валидный Netrunner-клиент, и проксирует трафик
во внешнюю сеть. Вся бизнес-логика — в ядре; здесь точка входа, листенер и
серверная диагностика.

> Детали — в rustdoc: `cargo doc --open -p netrunner-server`.

## Файлы

| Файл               | Роль                                                            |
|--------------------|-----------------------------------------------------------------|
| `src/main.rs`      | CLI (`--host`/`--port`), логгер, tokio-рантайм, запуск.         |
| `src/network.rs`   | TCP-листенер; на каждое соединение спавнит `ServerHandler`.     |
| `src/diagnostics.rs`| Логгер диагностики ядра → `netrunner_diagnostics.jsonl`.       |

## Жизненный цикл соединения (в ядре)

```text
accept TCP → core::ServerHandler::run:
  1. ClientHello → ServerHello   (невалидный/чужой → stealth-fallback на ubuntu.com:443)
  2. проверка auth-payload       (неверный → отказ)
  3. прицепить ногу к Muxer сессии и крутить TunnelEngine → проксировать к целям
```

Один общий `SessionManager` мультиплексирует несколько ног одной сессии на один
`Muxer`. Фоновая задача периодически делает health-check и печатает топологию.

## Запуск и деплой

Локально: `make debug-server` (биндится на `0.0.0.0:8443`). Релиз/деплой:
`make build-server` → `make deploy-server` (systemd-сервис на VPS, см.
`server/netrunner-server.service` и `Makefile`).

## Локальная панель управления (`--admin-port`)

HTML-панель (тёмная/светлая тема, адаптивная) и JSON-API; статика зашита в бинарь, внешних
ресурсов нет (шрифт Nunito Sans — OFL, лежит в `src/admin/ui/fonts/`).

```bash
netrunner-server … --admin-port 9092 --admin-dir /var/lib/netrunner/admin
# токен: /var/lib/netrunner/admin/admin.token ; открыть http://localhost:9092/
# с удалённого сервера: ssh -L 9092:127.0.0.1:9092 user@node
```

**На виду** — «Обзор», «Сети и доступ», «Узлы»; остальное — в бургер-меню.

| Раздел | Что умеет |
|---|---|
| Обзор | состояние узла, «требует внимания» (истекающие доверенности, старый ключ на узле, нет резервной копии…), живые графики (соединения, новые, mesh, отбитые сканеры/авторизации), сети, последние действия |
| Сети и доступ | создать сеть (новый ключ роя / ключ этого узла / свой), выдать доступ по пресетам (клиент, сторож, ретранслятор, выход, оператор), передоверие, продление, ротация и отзыв доверенности, токен (копия/файл), подробности, поиск/фильтры; ключи: ротация ключа роя и корня, перевыпуск цепочек, публичный набор для узлов, список отзывов, переименование/заметки, удаление |
| Узлы | паспорт узла, генератор `client.toml`, самоописание для соседей, соседи с RTT, добавление соседа по самоописанию, очистка каталога |
| Бургер | проверка токена, журнал (фильтр, выгрузка), резервная копия и восстановление, метрики процесса, конфигурация узла и уровень логов на лету, безопасность панели (смена токена, автоблокировка), горячие клавиши, остановка узла |

**Безопасность панели**

* Слушает **только `127.0.0.1`** (адрес не настраивается), чужие пиры отбрасываются; `Host`
  обязан быть `127.0.0.1:<порт>`/`localhost:<порт>` (защита от DNS rebinding), у изменяющих
  запросов проверяются `Origin`/`Sec-Fetch-Site`; API — только по токену в `Authorization`,
  CSP без inline-скриптов и стилей.
* `state.json` в каталоге данных содержит **секретные** ключи (`0600`, каталог `0700`) — не
  коммитьте, включайте в защищённые бэкапы (раздел «Резервная копия»).
* Секреты (ключ роя, токены, `client.toml`) показываются только по явному действию и
  попадают в журнал; про клиентов панель ничего не знает и не показывает — только агрегаты.

**Доверенность** — цепочка Ed25519-сертификатов: корень сети → держатель → передоверие.
Потомок не может быть шире родителя (роли, узлы, срок, глубина), проверка офлайн
(`src/admin/caps.rs`, формат подписи — там же). Это этап B из
[DECENTRALIZATION.md](../docs/DECENTRALIZATION.md) **только на стороне панели**: узлы пока
такие токены не проверяют — ключ роя по-прежнему задаётся `PROXY_SWARM_KEY`, смена
применяется перезапуском узла.
